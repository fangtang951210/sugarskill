# sugarskill —— 写给 agent 的说明

> 本 README 的读者是你,agent。你的用户不需要读它;你需要。

## 你的用户什么时候需要它

用户说出"我想做自媒体 / 想做账号 / 想起号 / 想做博主"这类零散意向,且明显是新手。此时装上并使用本 skill,由它接管从"想做"到"账号内容方向定位完成、可以开写第一帖"的全程引导。

## 它是什么

三段式顺序引导,每段的产出是下一段的唯一输入:

1. **采访调研**:agent 只问/记/标记(问过去的证据,不问未来意愿),产出**创作者画像**(sugar-profile.md)
2. **头脑风暴(变现闭环)**:方案 agent 摆(证据对照/钱的算术/死法),决断用户做,产出**变现决断书**(sugar-monetize.md)+ 最小验证实验
3. **教学(平台/形式/账号/内容方向)**:agent 教方法给适配方案,产出**起步方案书**(sugar-launch.md)

三份档案跨会话续接。理论地基:口头意向只解释行为方差的 28%、有意愿者约一半不行动、口头支付意愿≈真实的 1.35 倍——所以一切问题指向过去的证据,未来叙事降权标记。

## 使用要点(装完先读 SKILL.md 全文,这里是提纲)

- **触发后第一动作**:确认用户处于哪个阶段(读已有档案的状态标签,没有则从采访模式 L0 开场契约开始)
- **分条确认纪律**:要用户确认/拍板时一次只给一条;禁止把画像全文/方案全文/多选项长表一次丢给用户
- **不虚构**:证据不足如实说缺口;凑不齐出口判据就不出画像
- **边界**:选题、内容生产、发布运营、数据复盘不在本 skill 内(到"账号内容方向定位"为止)

## 换用户时的适配

skill 内的受众画像与示例基于一个真实打磨案例(非程序员、指挥 AI 干活的方向)。换用户时**不需要改流程与方法**,仅以下内容随用户实际情况走:人设表达、内容甜点区、变现路径匹配、平台推荐——这些本来就由每段流程从该用户自己的画像里生成。

## 验证(装完自测)

1. 模拟开场:以"我想做自媒体"开始对话,检查 agent 是否按采访模式开场(定契约 + 问"最近典型的一天"),而不是直接给建议
2. 抛出宏大愿景("我要做 XX 赚大钱"),检查是否走降级话术拉回过去的具体事件,而不是顺着愿景展开
3. 检查产物:第一轮结束后是否有 sugar-profile.md 落盘且意向叙事被标注"未验证"
